Set up hosted product monitoring

Create a Pipedream workspace and a Connect project at https://pipedream.com/connect. Development projects are available for setup and testing. The project owner chooses the production subscription through Pipedream billing.

Create a server-side OAuth client restricted to the Connect project. For public-key authentication, register an EC P-256 public JWK with Pipedream and keep the matching PKCS#8 private key in the deployment secret store. Put these server-only settings in the RegPilot deployment's private environment, then redeploy that environment.

REGPILOT_PIPEDREAM_PROJECT_ID
REGPILOT_PIPEDREAM_CLIENT_ID
REGPILOT_PIPEDREAM_PRIVATE_KEY (or REGPILOT_PIPEDREAM_CLIENT_SECRET for a shared-secret client)
REGPILOT_PIPEDREAM_ENVIRONMENT

Use development for testing and production for the paid customer-facing project. RegPilot's workspace database, authorised sign-in, private connector encryption key, connector worker and REGPILOT_CONNECTORS_ENABLED must be configured. RegPilot verifies the project ID and reads the number of linked accounts during the staging deployment check. The private key and account tokens stay in the server environment.

In Company integrations, open Hourly product monitoring. Choose the product read, authorise the customer's account, refresh the linked accounts and read a sample. Select the receiving control and approve the sample. The worker rechecks the account grant and compares the returned identifiers hourly. Raw records stay out of RegPilot's stored comparison. Missing permissions, changing pages, very large results or unsupported identifier shapes can limit an individual integration.

A new account can show a negative health flag while the provider accepts its authorised reads. RegPilot tests the selected account directly and verifies the grant again after the read. A rejected credential pauses the monitor. In Accounts requiring renewal, reauthorise the original account, then verify the updated grant. The next successful scheduled run supplies the recovery evidence. GitHub repository inventory checks access, recent activity, merged-branch cleanup, secret scanning and push protection. For up to four returned repositories per run, RegPilot verifies available settings on the single-repository endpoint using the same grant. Unavailable settings appear as unknown. Different products can expose different breadths of inventory through their published read.

Counts of published actions, actually connected accounts and sustained hourly monitoring are available separately. Customer ownership, real cadence and observed recovery require customer records in the private workspace.
