# Obligation library and relationship analysis

Implemented in the existing Next.js / Prisma / Supabase architecture. New functionality is disabled by default. This is a development implementation, not a live regulatory-content service or a validated competitor performance result.

## User workflow

1. In `/team/library`, save structured business facts and UK nations. Unknown facts remain unknown, including under negation. Rules support nested all/any/not groups, numeric thresholds and explicit nation membership. A rule match is a recommendation for human applicability review, not a legal decision.
2. Find GOV.UK publications through the bounded official Search API. Register and capture a relevant publication. Registration validates Content API identity, rejects redirects/withdrawn pages and permits only canonical GOV.UK paths. Each organisation may register up to 200 publications beyond the 14 seed references. Registered sources work with existing independent source review, manual comparison, daily/weekly watch schedules and semantic interpretation. Registration alone does not start a schedule.
3. Import selected candidates from an existing rule/AI source analysis into a named collection, preserving quoted conditions and exceptions. Alternatively import exact clauses from a reviewed source snapshot or an independently approved clean private PDF. The API supports 25 clauses per bounded 64 KiB request; the simple clause form handles one at a time. PDF processing uses the existing isolated real parser; incomplete extraction blocks intake. Rights and processing consent are required. This does not supply licensed standards content.
4. Independently approve a requirement revision, then record applicability and an active owner. Reference + collection identify a stable requirement; revisions keep provenance, exact text, conditions, exceptions, source anchors, hashes, authors and review history. Accepted heads supersede earlier revisions. A source must be the latest reviewed snapshot, verified within seven days. A changed source or business-profile version invalidates applicability. A new revision requires a fresh decision.
5. Compare up to 12 currently applicable requirements with 30 accepted managed controls and optionally three independently approved PDFs. Local text retrieval returns potential relationships; a separately gated AI route can propose partial/conflicting relationships. The 65,000-character selection limit, bounded model output, timeout, request quotas, reservations and three-attempt explicit retry limit bound work. AI never executes tools or approves anything. Exact requirement/control/evidence quotations and IDs are validated before proposals are retained; unsupported proposals are counted and discarded.
6. A different administrator reviews each relationship. Conflicts cannot be accepted. Multiple collections can share one control, but each relationship has its own scope rationale and decision. This is not certified framework equivalence or evidence sufficiency. Existing source-task assurance completion gates remain separate.
7. Inspect change impact and generate owned follow-up tasks. Context binds source and requirement revisions, business facts, applicability version, control/programme state and evidence versions. Removed/inactive owners, changed original programme evidence, redacted content or stale publications invalidate relationships. One review task per affected decision is generated under the organisation lock; duplicate requests reuse it. A seven-day target is operational, never inferred as a legal deadline. Tasks are generated by an administrator's request; no new unattended impact scheduler is claimed.

## Scope and limits

- 1,000 requirement identities per organisation; list pages contain 25, with current approved heads retained even after later rejected drafts. Version history shows the latest 50 revisions; analysis lists show the latest 20; selectable controls/evidence show up to 200/50. Impact inspects up to 100 latest decisions and explicitly reports truncation. Counts describe that bounded relationship window, not a whole-business compliance score.
- UK-first discovery currently uses GOV.UK only. It is not a complete UK, devolved-nation, regulator or court corpus. The existing fetcher analyses a bounded publication-body excerpt; PDF annexes and external regulatory sites are not automatically crawled. Document type and territorial/legal interpretation require expert review.
- Clause scope rules and reviewed mappings are created by users, not sold as expert-certified legal content. There is no hidden built-in ISO/SOC clause corpus.
- Quotation grounding verifies textual support, not semantic correctness. Local retrieval is keyword overlap. AI quality, hallucination rate and SME task success have not been evaluated against a live, expert-labelled benchmark. Tests inject model outputs and use fictional material.
- No OCR/DOCX, commercial content licence, new customer connector providers, public auditor accounts, SSO/SCIM, production throughput guarantee or automatic legal-deadline determination is supplied by this batch.
- Existing AI gating requires configured authentication, invitation allowlist, safeguards attestation and provider configuration. Request quotas are not a monetary budget. Do not activate paid/confidential processing until enforceable spend, privacy and service safeguards have been independently verified.

## Retention and integrity

Requirement redaction removes its saved content/provenance/review notes and applicability rationale, and clears all related coverage runs and mapping rationales. Coverage redaction removes saved quotations and context. Redaction stays available to authorised administrators while feature flags are off and fences in-flight output. Audit identifiers, immutable source snapshots and original evidence have separate retention; this is not a complete data-subject erasure service. Hashes detect record changes; they are not digital signatures or independently notarised audit proof.
