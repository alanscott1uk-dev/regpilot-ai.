# Monitoring, grounded interpretation and change impact — 7 November 2026

This development batch extends the existing Next.js, Prisma, Supabase and AI Gateway architecture. It adds real implementation and isolated tests. It is not deployed or activated. No paid model requests, hosted migrations or customer-data processing are required to test it.

## Completed behaviour

- Administrators save daily or weekly schedules for the six allowlisted public GOV.UK references. Schedules persist in PostgreSQL. The inbox distinguishes awaiting activation, waiting for a first check, scheduled, checking, retry scheduled, overdue, paused and attention required.
- A secret-authenticated POST worker claims at most two due schedules per invocation. PostgreSQL `FOR UPDATE SKIP LOCKED` claims a schedule atomically. A random lease token fences old workers; expired leases can be reclaimed after 90 seconds. Pausing or editing a schedule invalidates its current lease.
- Current administrator membership and pilot allowlisting are checked before retrieval and under database locks before writes. Revoked access pauses the schedule. Tokens and raw provider errors are never returned by the workspace API.
- Each successful retrieval saves or refreshes an exact source snapshot. If a business profile exists, deterministic review work is prepared automatically. A retry reuses the source checkpoint and unique source/profile/engine analysis. Source retrieval does not make a paid AI call, accept a recommendation, create a task or send a message.
- Failures retry after five then thirty minutes; the third failed attempt pauses the schedule. Interrupted claims also consume attempts. A fourth claim following three expired leases pauses without another fetch. Last successful check is preserved across failures. Missed periods are coalesced into one check rather than replaying an unbounded backlog.
- Manual AI interpretation uses the installed AI SDK structured-output API. It extracts draft subjects, actions, duties, prohibitions, recommendations, exemptions, conditions and date passages. It can represent duties without a `must` keyword. The system prompt treats source content as untrusted data, with no tools available.
- Each retained main quote, condition, exception and date passage must be a unique exact substring of the current stored source. Missing, stitched or ambiguous quotes withhold that entire proposal. The inbox retains surrounding context. Exact quotation validation does **not** establish the truth of an interpretation, applicability, legal status, completeness or source authority.
- AI control suggestions are restricted to eight existing internal themes. No invented certified framework IDs are accepted. No legal deadlines are inferred, and exemptions retain their classification.
- Consent specifies exactly what is sent: a public excerpt, its source ID, previous excerpt and the selected business categories/nations. No organisation name, user identity, customer document or evidence file is sent by this route. Draft output is persisted for independent review.
- A durable unique request reservation prevents concurrent provider calls for the same organisation/source/profile/engine. The existing organisation/user daily allowance is reserved before generation. SDK retries are zero. Interrupted or failed attempts cannot silently rerun and incur another charge. Source, membership, allowlist, profile and activation flags are rechecked before results are saved.
- A changed source also surfaces previously accepted tasks and the number of attached evidence files based on older source text. This includes completed tasks. Reviewers decide whether anything needs changing; source drift does not silently revoke approvals or change task status. Results are bounded to 100 affected decisions, with truncation disclosed.

## Operational and cost limits

All new activation flags default to false. `REGPILOT_MONITORING_ENABLED` enables the worker; it does not install a scheduler. `REGPILOT_MONITOR_SECRET` must be a random server-only secret of 32–256 characters. A separately configured scheduler would POST to `/api/internal/monitor` with bearer authentication. No Vercel cron or other paid service has been provisioned. Trigger frequency/capacity must be load-tested against the two-schedule batch size; overdue state must be monitored.

`REGPILOT_SEMANTIC_ENABLED`, the existing AI configuration and `REGPILOT_AI_SAFEGUARDS_VERIFIED` are all required for semantic generation. The last flag is an operator attestation, not an automated security certification. Before enabling it, verify real authentication and tenant isolation, provider processing/retention/privacy terms, account and model permissions, provider-enforced spend limits, usage reconciliation and incident response. Request counts are not a currency spend limit. These gates have not been completed here, so paid calls remain disabled.

The source catalogue still contains six selected references, not full UK regulatory coverage. GOV.UK excerpts remain bounded and may omit linked pages, tables and context. Source monitoring is polling, not a real-time change feed. There are no new external evidence collectors, SCIM/SSO enrolment flows, or licensed framework mappings in this batch. Semantic generation quality has not been measured against an expert-labelled real regulatory corpus. Mock model tests verify the adapter and safety contracts, not the intelligence of a live model.

## Verification and migrations

Unit tests exercise invented/ambiguous/stitched citations, retained exceptions and context, unknown control IDs, output limits, SDK structured generation with a mock model, no automatic provider retries and API authentication/activation failure paths. Fictional sources deliberately avoid real legal advice.

PostgreSQL integration tests exercise competing claims, lease expiry/recovery, pausing during retrieval, role revocation, tenant isolation, bounded retries, preserved success timestamps, no paid monitoring calls, single AI reservation, independent decisions, profile changes during generation, failure deduplication, and source-to-existing-task impact. CI also tests Data API denial for the two new tables, the existing workflows, the production build and gated page/API smoke checks.

`fixtures/schema-db6e5e0.prisma` is the prior exact schema. `prisma/changes/monitoring-semantic.sql` is an additive transaction from that baseline, including default-deny private-table hardening before commit. CI applies the previous `obligation-intelligence.sql`, then this delta, and checks schema drift. Do not apply to a live database before verifying its actual baseline and recovery plan. No hosted database migration was performed.

The app still requires real-provider staging acceptance, browser session and visual/accessibility testing, model accuracy evaluation, load/cost measurement and independent security review before release. Preview deployments remain disabled and PR #10 remains draft.
