# Access reviews, customer assurance and audit preparation

This development batch adds complete workflows for three gaps identified in the competitor review. It retains the existing Next.js, Prisma, Supabase Auth, private Evidence Vault and organisation permissions. It makes no AI or paid-provider calls and activates no provider, scheduler, email delivery, hosted migration or deployment.

## Review who has access

Open `/team/access-reviews`. An administrator imports a complete CSV for one system, with `account,permission,privileged,active` headers and strict `true`/`false` values. The administrator declares when the source was observed and confirms completeness. The latest observation must be within seven days; an older observation cannot replace a newer one.

Create a campaign from the latest inventory with a primary reviewer and a different backup. Known account/email matches go to the backup, and reviewers cannot decide on their own known account. Each active permission is reviewed separately. A colleague sees only items they review or remediate.

The reviewer records a reason to keep, remove or change a permission. Removal/change creates an owned task. The operator makes the change in the actual source system; RegPilot never changes access. An administrator imports the complete refreshed inventory, and the operator submits independently approved supporting files. A separate administrator verifies current permissions and the actual stored file bytes. Completing the task directly cannot substitute for verification.

A separate administrator closes the campaign only after every item remains current. New unreviewed permissions, a stale inventory or changed evidence block closure. Reassignments require an undecided item; resetting a decision preserves its history. Team role changes hand over pending reviews and open remediation tasks. Cancellation records unfinished tasks as exceptions. The downloadable internal record preserves the reviewed inventory, decisions, evidence, identities and history, and reports whether the closure still matches the current context.

This is a point-in-time review of a human-declared population. CSV import cannot prove completeness, link aliases to real people, discover providers or enforce source-system revocation. These limits appear in the workflow and export. Bounds: 200 records per inventory, 300 inventories and 100 campaigns per organisation, 20 historical item revisions, ten files per proof, 50 distinct files at closure. Equivalent sorted inventories have the same content fingerprint; they still need a fresh observation.

## Answer customer questions and share reviewed proof

Open `/team/answers`. A writer drafts an answer with a question, business scope, review deadline and independently reviewed files. A different administrator from the author and file uploaders verifies stored bytes and approves the exact content. Revision preserves the earlier content/approval, returns the answer to draft and invalidates downstream disclosures. Withdrawal or expiry also prevents further use.

In `/team/questionnaires`, an administrator imports a CSV with `reference,question` headers, names the recipient/scope and assigns a colleague. One exact current approved answer in the same scope becomes a suggestion. Ambiguous matches stay unanswered. Similarity suggestions do not infer equivalence, generate prose or approve anything. Each assigned colleague explicitly confirms an answer for each customer question. Another administrator approves the complete disclosure after current evidence verification. Export produces a spreadsheet-safe CSV with answers, scope and filename/hash references; it does not send anything to the recipient. Reopening preserves the earlier approval and requires fresh confirmations.

In `/team/trust`, select that approved questionnaire, inspect its answer/evidence disclosure and publish a private room using the existing auditor-room access model. Referenced files are included automatically, up to 50 total. Access is granted only to named verified accounts, expires and can be revoked. The guest uses `/trust`, accepts the invitation and sees approved answers and selected evidence without staff identities, internal questionnaire identifiers or storage paths. A revised/withdrawn answer or changed evidence blocks the old room immediately. Reapproving a later questionnaire never silently revives the old share: create and review a new room.

Bounds: 300 answers per organisation; 100 questionnaires with at most 100 questions each; 20 historical answer/questionnaire revisions; ten supporting files per answer and 50 unique files per disclosure. CSV input is bounded at 200 KB. No automated AI generation, public Trust Centre, NDA signing, CRM workflow, outbound questionnaire submission or website publication is included. The original named-grant, expiry and revocation protections remain in force.

## Prepare an audit package

In `/team/audits`, choose up to ten current controls, an audit period, sample size and reproducible seed. Preview shows each control owner, the independently approved linked file population, selected sample and up to three previous published audit reviews. The exact preview binds control versions, owners, population, selected files, period and earlier review context. Applying it atomically creates a room and one owned request per control. Identical repeated submissions reuse the same result; changed evidence requires a fresh preview.

For each control, the candidate population is approved linked files **uploaded within the selected dates**. Upload time does not establish the period those files cover. A deterministic hash ranks candidates; it is not a statistical sampling opinion. The owner must state actual coverage, population and exclusions, and an independent administrator accepts or returns the submission. A nonempty planned sample must be submitted exactly; replacing inconvenient files requires a new reviewed plan. Empty populations create collection requests, not fabricated evidence or a passing result. A later quarantine/withdrawal blocks acceptance and publication.

After all requests are resolved, preview and publish the disclosure. The ZIP download contains the published manifest and actual verified file bytes, with safe filenames and a manifest-to-entry mapping. Permissions, expiry, room state, evidence currentness and questionnaire currentness are rechecked after retrieval. No object-store key is exported. The archive is limited to 50 files/30 MB of file content; the uncompressed ZIP writer also has a 32 MB total bound. Larger scopes must be split into reviewed packages. Guests retain individual scoped downloads; bulk archives are administrator-only.

Bounds: audit period at most 366 days ending no later than today; ten controls; five sampled files per control; 500 candidate files per control. Exceeding the candidate bound blocks the preview rather than presenting a partial population. Historical review notes are context, not evidence of present effectiveness. Audit packages are not certifications or digitally signed opinions.

## Security and verification

All new APIs authenticate before parsing input, use bounded bodies and return private uncached responses. Server-side current membership, organisation locks, serializable retries, expected versions and independent review protect writes. Composite foreign keys bind inventories, campaigns and remediation tasks to their organisation. Customer sharing reuses existing private audit grants without granting team membership.

Apply `prisma/changes/assurance-operations.sql` after `change-response.sql` only through the reviewed release process. `fixtures/schema-984141b.prisma` preserves the preceding schema. Five new tables (`AccessInventory`, `AccessCampaign`, `AccessReviewItem`, `AssuranceAnswer`, `AssuranceQuestionnaire`) bring the private-table set to 48; `AuditRequest` gains a nullable sampling plan. The additive migration includes default-deny Supabase Data API hardening in the same transaction.

Automated tests use fictional accounts, documents and a disposable PostgreSQL 17 instance with injected storage. They cover CSV syntax/bounds/formula safety, deterministic matching, independent ZIP parsing, API gates, tenant boundaries, self-review, stale inventories/evidence, storage corruption, revoked permissions during retrieval, concurrent creation/acceptance, role handover, disclosure approval, stale private shares, reproducible sampling, exact-sample enforcement, prior audit context and database constraints. The full migration chain, zero drift, 48 private-table policies, production build and 29-page smoke suite are required checks.

Before release, execute all three workflows with real staged Auth/Storage and fictional data on desktop and mobile. Record non-technical operator completion times and errors. Signed-in browser acceptance remains unverified: the managed preview runner supplied incompatible Vite flags to Next.js before serving. The framework was not changed to bypass that runner. Provider operation, regulatory mapping accuracy and competitor performance are separate acceptance claims, not conclusions from these tests.
