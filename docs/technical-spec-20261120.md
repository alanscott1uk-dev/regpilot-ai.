# RegPilot competitive technical specification — 20 November 2026

## Delivery order

The current user instruction is to add advanced capabilities and their supporting infrastructure first, bring the application to a defined technical specification, then complete workflow and visual refinement. This supersedes a workflow-only development priority. Every new capability still needs meaningful correctness, tenant-isolation and persistence verification as it is built; those checks are part of implementing the capability.

This is the active technical baseline. Historical feature notes must not be mistaken for current gaps or counted again as new development. A screen, connector name or mock response is insufficient evidence that a capability is implemented. The development branch and [PR #10](https://github.com/alanscott1uk-dev/regpilot-ai./pull/10) record the exact source revision, executed checks and remaining failures. A subsequent review deployment is a separate action; the 19 November preview does not contain this batch.

## Competitive requirements implemented in this batch

| Capability | Technical implementation | Boundary |
| --- | --- | --- |
| Real questionnaire file intake | Authenticated CSV/XLSX uploads; worksheet selection; question, reference, response and multiple context columns; row ranges; bounded preview; original file SHA-256 and sheet/row/A1 provenance | 3 MiB input, 16 MiB expanded ZIP, 256 entries, 3,000 source rows, 20,000 cells, 100 selected questions. Unsafe active content, macros, external relationships and formulas are rejected. PDF/DOCX questionnaire import remains outside this implementation. |
| Import integrity and recovery | Import reparses the exact original upload against the inspected digest and confirmed mapping. Only selected columns are retained. A unique request key returns the saved questionnaire after an uncertain response | Preview is not a durable write. Imported customer answers are unapproved context and cannot silently enter the approved company library. |
| Batch reuse of company knowledge | Complete answer text and evidence references; exact and related candidates; scope restrictions; supported, ambiguous, conflicting, expired and unanswered queues; knowledge-health counts | Related matching uses word relevance, not semantic AI confidence. Conflicts identify differing answers to equivalent questions; they are not a general semantic contradiction detector. |
| Atomic batch preparation | A read-only preview is bound to the questionnaire, answer versions, files and current participants. Explicit selected application verifies original bytes and writes all selected suggestions atomically | Applied suggestions require the assigned owner to confirm relevance. Independent disclosure approval remains separate. No blanket auto-approval. |
| Evidence passage retrieval | Private PDF and DOCX bytes are downloaded and hash checked, then parsed in bounded extraction workers. Search returns exact page or Word-block quotations and offsets | Search locates related text; it does not compose a response or determine sufficiency. Incomplete extraction cannot be used to save a supported answer. |
| Evidence-grounded AI responses | The installed AI SDK makes a real structured model call with the configured model, no tools, bounded input/output, timeout and zero automatic retries. Every retained response paragraph must have exact unique quotations in the selected private evidence | Exact anchors do not establish semantic correctness. Missing or ambiguous citations withhold a paragraph. Paid/model configuration and a dedicated questionnaire flag must be activated before hosted use; controlled provider tests are not a live AI accuracy evaluation. |
| Persistent preparation records | New `QuestionnaireDraftRun` table records PROCESSING/DRAFT/SAVED/FAILED states, request and input hashes, engine version, evidence manifest, source context, result hash, answer link and failure code | Same-request recovery never repeats a model call. A new key cannot bypass identical-input deduplication. Interrupted preparation becomes visibly failed; it is not automatically re-billed. Explicit same-input retries after a failed attempt remain a separate, unimplemented recovery capability. |
| Currentness and version control | Recheck question scope, assigned owner, evidence review/version and current creator/uploader/reviewer authority before generation commits and before an answer saves. Re-verify original bytes and exact citations during save | Changing another question does not unnecessarily invalidate an unchanged question's evidence basis. Changed selected evidence or participant authority blocks reliance. |
| Reusable answer creation | The author can edit a generated or evidence-supported response and explicitly save it into the existing answer library as DRAFT, with provenance linked to the preparation | Independent answer approval, question-owner confirmation and independent customer disclosure approval remain necessary. Editing is not represented as AI validation of the edit. |
| Response pack export | Approved responses export as clean values-only XLSX or CSV, in selected source order, with provenance and current evidence references | XLSX is a new clean workbook. Original formatting, merged cells, validations, formulas, macros and the customer's file structure are not preserved. Original private documents are not included in the workbook. |

### Implemented infrastructure

- Additive schema migration with composite company/questionnaire and company/answer foreign keys, unique operation/input constraints, state checks and indexes. The new table is closed to Supabase Data API roles in the same migration. The restricted staging application role receives only its existing private-runtime pattern when present.
- Short serializable company transactions and membership locks protect state changes. Draft history and reusable answer-library checks read shared evidence and participant state in bounded bulk projections rather than querying them again per record. Storage retrieval, extraction and model calls execute outside transaction locks; final state is recaptured before commit.
- Existing organisation/platform paid reservations and per-user/per-company AI quotas apply. Questionnaire preparations additionally have a bounded daily organisation allowance. Failed or interrupted paid attempts remain counted because a provider may have accepted them.
- Production package traces include the PDF and DOCX workers and parser dependencies for both prepare and save routes. Isolated runtime tests exercise the packaged workers rather than relying on development imports.
- Database, HTTP, domain and file-parser tests are registered in the existing CI. The new additive migration is included in the baseline-to-current schema drift check and the private-table checks.
- The interface exposes technical capabilities through the existing company context, with explicit unknown-outcome recovery. It is not a second disconnected application or a simulation of provider behaviour.
